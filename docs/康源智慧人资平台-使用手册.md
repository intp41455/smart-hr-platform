**考勤判定规则**：

| 状态   | 判定标准                  | 扣款          |
| ---- | --------------------- | ----------- |
| 正常   | 打卡时间在班次±5分钟内          | —           |
| 迟到1级 | 迟到 1-5 分钟             | ¥10         |
| 迟到2级 | 迟到 5-15 分钟            | ¥30         |
| 迟到3级 | 迟到 15-30 分钟           | ¥50         |
| 迟到4级 | 迟到 >30 分钟             | 按旷工半天       |
| 早退   | 同迟到分级标准               | 同迟到         |

| 旷工半天 | 迟到/早退 >30分钟 或 无理由缺勤半天 | 扣 1.5 倍日工资  |

### 3. 薪酬核算

**操作入口**：点击「自动核算工资」按钮

**计算流程（12 步）**：

```
Step 1-4   岗位标准工资 → 日工资(÷21.75) → 全勤奖 → 工龄工资
Step 5     各类补贴（餐补/交通/通讯/岗位）
Step 6     加班费（工作日不计、公休日存休）
Step 7-10  扣款：病假(80%/50%/最低80%) → 事假 → 迟到 → 旷工
Step 11    应发 = 标准 + 全勤 + 工龄 + 补贴 − 扣款
Step 12    实发 = 应发 − 社保 − 公积金 − 个税
```

**展示区域**：

| 区域        | 内容                        |
| --------- | ------------------------- |
| 汇总卡片（4 张） | 应发总额、实发总额、社保公积金、核算人数      |
| 柱状图       | 各主体应发 vs 实发对比             |
| 明细表       | 逐人应发/社保/个税/扣款/实发/校验状态     |
| 审计轨迹      | 每步计算规则 ID、公式、输入输出，最多 30 条 |

**社保公积金费率**：

| 项目  | 个人   | 单位    |
| --- | ---- | ----- |
| 养老  | 8%   | 16%   |
| 医疗  | 2%   | 8%    |
| 失业  | 0.3% | 0.7%  |
| 工伤  | —    | 0.32% |
| 公积金 | 5%   | 5%    |

**个税**：累计预扣预缴法，起征点 ¥5,000/月，7 级累进税率（3%~45%）。

### 5. 规则引擎 ⭐

**核心能力：自主增删改查**

**筛选方式**：

| 方式   | 说明                               |
| ---- | -------------------------------- |
| 搜索框  | 匹配规则 ID / 名称 / 公式 / 条件           |
| 分类标签 | 全部 / 考勤 / 薪酬 / 校验 / 扣款 / 加班 / 请假 |

**CRUD 操作一览**：

| 操作     | 入口          | 效果                        |
| ------ | ----------- | ------------------------- |
| **新增** | 右上角「＋ 新增规则」 | 弹窗填写 11 项字段，保存即生效并写入数据库   |
| **编辑** | 行内「编辑」按钮    | 弹窗修改，rule_id 不可改，其余字段任意编辑 |
| **删除** | 行内「删除」按钮    | 二次确认后软删除（设为停用，不物理移除）      |
| **开关** | 点击状态标签      | 一键切换启用 / 停用               |

**规则分类**：

| 分类              | 数量   | 典型内容                                |
| --------------- | ---- | ----------------------------------- |
| 考勤 (attendance) | 28 条 | 工时制度、迟到/早退/旷工/补卡/缺卡/全勤/请假/加班存休      |
| 薪酬 (salary)     | 17 条 | 薪酬结构、日工资、全勤奖、工龄工资、扣款公式、社保、个税、入职离职折算 |
| 校验 (validation) | 4 条  | 考勤天数校验、工资波动预警、零工资校验、社保基数校验          |

**关键公式速查**：

```
日工资 = 标准工资 ÷ 21.75        （劳社部发〔2008〕3 号）
时工资 = 日工资 ÷ 8
应发 = 标准工资 + 全勤奖 + 工龄工资 + 补贴 − 各项扣款
实发 = 应发 − 社保(10.3%) − 公积金(5%) − 个税
病假 ≤7 天 → 发 80%;  7-15 天 → 发 50%;  >15 天 → 发最低工资 80%
旷工半天 → 扣 1.5 倍日工资;  全天 → 扣 3 倍日工资
全勤奖 = ¥100/月（无迟到/早退/缺卡/请假/旷工）
```

> 💡 **月中入职/离职**：日工资分母用**当月应出勤天数**（非 21.75），按实际出勤天数 × 日工资计算。

## 四、典型操作流程

### 月度薪酬核算（完整链路）

```
① 选择月份 → ② 考勤管理 → ③ 自动计算考勤
    → ④ 薪酬核算 → ⑤ 自动核算工资
    → ⑥ 员工管理 → ⑦ 点击「工资单 →」查看明细
    → ⑧ 规则引擎 → ⑨ 如需调整规则，编辑后重新核算
```

### 新增一条规则示例（居家办公工资折算）

1. 进入「规则引擎」
2. 点击「＋ 新增规则」
3. 填写：
   - 规则 ID：`R-SAL-025`
   - 名称：`居家办公工资折算`
   - 分类：`salary`
   - 子分类：`deduction`
   - 优先级：`30`
   - 公式：`deduction = daily_wage × remote_days × 0.3`
   - 说明：`经审批的居家办公期间按日工资 70% 计发`
   - 法规依据：`劳社部发〔2008〕3 号`
4. 点击保存 → 绿色 Toast 提示「规则已创建」
5. 新规则立即生效，下次核算自动参与计算

## 七、FAQ

**Q：为什么有的员工核算后工资为 0？**  
A：检查该员工当月考勤是否已计算。先跑「自动计算考勤」，再跑「自动核算工资」。

**Q：修改规则后需要重新核算吗？**  
A：需要。规则引擎的修改影响**后续计算**，已有记录不会自动回溯。修改规则后重新点击「自动核算工资」即可用新规则覆盖。

**Q：删除的规则能恢复吗？**  
A：删除是软删除（active=0），不会物理移除数据。如需恢复，在数据库中手动将 `active` 改为 `1`，或通过 `rules/sync-force` 重新导入。

**Q：考勤数据能接真实钉钉吗？**  
A：可以。当前 `attendance.js` 中的 `generateMockAttendance()` 替换为钉钉 API 调用即可。API 对接参见钉钉开放平台文档。

**Q：试用期员工工资怎么算？**  
A：R-SAL-004 自动处理——试用期员工标准工资按 80% 折算，社保公积金正常缴纳。

## 八、云部署（Railway，免费）

> 应用已配置 `railway.json`，**前后端合并为一个 Node 进程**，云平台自动 `npm install → npm run build → npm start`，对外提供统一 URL。

### 部署步骤（无需 CLI，GitHub 一键关联）

1. 打开 https://railway.app ，用 **GitHub 账号登录**
2. 点击 **New Project** → **Deploy from GitHub repo**
3. 授权后选择仓库 **`intp41455/kangyuan-smart-hr`**
4. Railway 自动读取 `railway.json`：
   - 构建：`npm install && npm run build`
   - 启动：`npm start`（Express 同时托管前端 + `/api`）
   - 健康检查：`/api/health`
5. 部署完成后，在 **Settings → Domains** 生成公开 URL（形如 `xxx.up.railway.app`）
6. 把该 URL 发给同事即可，**不再依赖你本机开机**

### 注意事项

- **免费额度**：Railway 需绑定支付方式，含每月免费额度；超出按量计费。
- **数据库**：SQLite 文件存于容器临时文件系统，**容器重启/重新部署后数据会重置**，首次启动自动重新播种（79 名员工 + 59 条规则）。生产环境建议改用云数据库（Postgres）。
- **原生依赖**：`better-sqlite3` 为原生模块，Railway 构建环境会自动编译，无需手动处理。
- 同等流程也适用于 **Render**（仓库已含 `render.yaml`）。
